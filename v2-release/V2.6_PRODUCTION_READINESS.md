## 2. Persistence

Required invariants:
- immutable snapshots reject conflicting payloads;
- identical immutable writes are idempotent;
- immutable event identity includes namespace, event type, payload,
  input/output hashes and provenance record;
- concurrent writes do not leak raw database uniqueness failures;
- atomic snapshot pairs commit together or not at all;
- SQLite and PostgreSQL implement the same observable contract;
- restart preserves snapshots, events, ledger, journal and provenance.

- PR #1: SQLite race-safe immutable persistence and adversarial coverage.

## 4. Recovery / crash consistency

Required crash boundaries:
- before intervention;
- after intervention starts;
- after after-snapshot capture;
- after ledger commit;
- before terminal journal event;
- after terminal journal event;
- duplicate recovery request;
- missing/tampered snapshot;
- existing ledger with missing terminal journal.

Core invariant:

EXECUTED != VALIDATED != CERTIFIED != COMPLETED

If an intervention outcome is unknown, recovery must close the attempt as
INTERVENTION_OUTCOME_UNKNOWN without silently rerunning the intervention.

Status: IMPLEMENTED / FULL RC EXECUTION PENDING

## 5. Transformation contract integrity

Required:
- required state/preconditions are checked against the durable before-state;
- expected changes are checked against the durable after-state;
- allowed/forbidden changes are enforced;
- postconditions are checked before certificate issuance;
- failed/partial/rollback-failed transitions are not certificate eligible;
- certificate identity remains content-derived;
- ledger identity and payload hash remain immutable;
- idempotent replay does not execute the intervention again.

Production-hardening PR #2 adds enforcement for previously declared
required_state and postconditions.

Status: IMPLEMENTED ON PR #2 / CI PENDING

## 6. Evidence graph / Science Lab

Required lineage:

Dataset → Analysis → Result → Run → Transformation → Claim → Report

A claim backed by a transformation requires both trusted durable transformation
provenance and graph lineage connecting the analysis run to the result and
transformation.

Mutable Science Lab provenance must never override the durable binder.
Backup/restore must preserve this lineage.

## 7. Error handling

Required:
- stable machine-readable error codes;
- no silent conversion of unknown outcomes into success;
- rollback failure is explicit;
- partial state is explicit;
- provenance failures block validation;
- version/idempotency conflicts remain distinguishable.

Transformation error-code contract includes:
PRECONDITION_FAILED, COMPATIBILITY_FAILED, UNKNOWN_COMPATIBILITY,
PROTOCOL_INVALID, DETOX_REQUIRED, STABILIZATION_REQUIRED,
INTERVENTION_FAILED, INTERVENTION_OUTCOME_UNKNOWN, STATE_CAPTURE_FAILED,
NO_STATE_CHANGE, UNEXPECTED_CHANGE, INVARIANT_FAILED, VALIDATION_FAILED,
PROVENANCE_FAILED, VERSION_CONFLICT, IDEMPOTENCY_CONFLICT,
ROLLBACK_FAILED, and PARTIAL.
