## Rollback guard coverage added after the baseline

The migration rehearsal now verifies three cases:
1. `runtime_snapshots` contains a sentinel row: rollback is rejected and the row/tables remain.
2. `runtime_events` contains a sentinel row while snapshots are empty: rollback is rejected and the event/tables remain.
3. Both runtime tables are empty: rollback succeeds and removes the runtime tables.

These checks exercise the guard against both independent data-bearing tables. The migration rehearsal is a safety test, not a substitute for a production backup/restore drill.

## Release boundary

The repository tests do not establish that the system has been empirically validated as a scientific model. Scientific status remains `IMPLEMENTATION_BASELINE` unless separate empirical evidence changes it.

Environment-specific production controls remain outside this repository verification record unless separately rehearsed in the deployment environment: external IAM/secret rotation, encrypted off-site backups, scheduled restore drills, distributed rate limiting, operational alerting and named operational ownership.

## Release decision

Do not infer a production deployment from this record alone. Tag `v2.6.0-rc1` only after:
- all required checks pass on the exact commit intended for the tag;
- the release owner records deployment decisions for environment-specific controls;
- no known P0/P1 defects remain;
- the exact tag SHA is confirmed to be the green candidate SHA.
