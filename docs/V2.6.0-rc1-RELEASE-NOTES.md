## Verification boundary

The repository CI verifies the executable software contract, including:
- full backend pytest suite;
- test collection;
- frontend JavaScript syntax;
- transformation concurrency/deadlock regression;
- live PostgreSQL integration;
- migration up/down rehearsal;
- RC gate verification.

These checks do not substitute for:
- production secret management and rotation;
- TLS/ingress;
- production IAM/SSO;
- encrypted off-site backup storage;
- scheduled backup and restore drills;
- distributed rate limiting;
- operational monitoring and alerting;
- production ownership and change-management approval;
- empirical scientific validation.

## Upgrade / rollback principle

Before destructive production changes:
1. Create a logical runtime backup.
2. Validate its manifest hash.
3. Restore and verify into an isolated environment.
4. Record the exact application/schema version and candidate commit.
5. Use controlled migration or restore for populated databases.
6. Re-run integrity/provenance checks before returning to service.

The guarded PostgreSQL down migration is intentionally not a production data-deletion shortcut.
